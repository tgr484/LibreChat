# Контракт DocHub для «Агентов DocHub» в LibreChat

Задание для доработки DocHub (`/home/ben/Repos/dochub`). LibreChat уже пишется по этому
контракту: всё, что ниже помечено **обязательно**, — формат обмена, менять его нельзя без
согласования. Внутреннее устройство DocHub — на усмотрение исполнителя.

## Зачем

В LibreChat появляются агенты, закреплённые за одной коллекцией DocHub. Пользователь может
поделиться таким агентом с другими пользователями LibreChat. Чтобы получатели могли им
пользоваться, коллекция должна быть публичной. LibreChat показывает автору предупреждение
(что именно станет публичным) и после подтверждения переводит коллекцию в публичную через
интеграционный API.

Сейчас интеграционный API только читает и не сообщает, публична ли коллекция и какова роль
пользователя в ней. Нужны два изменения: поля в ответах и маршрут публикации.

Все маршруты — под `/api/integration/v1`, с той же авторизацией
(`require_integration_user`, права пользователя, `is_admin` всегда `false`), тем же
аудитом (`_AuditedRoute`) и в том же формате ошибок `{"detail": "<code>"}`.

---

## 1. Поля `is_public` и `role` в карточках коллекций — обязательно

`GET /collections` — в **каждой** карточке всех трёх разделов (`my`, `shared_with_me`,
`public`) добавить:

| Поле | Тип | Значение |
|---|---|---|
| `is_public` | `bool` | `collections.is_public` |
| `role` | `"owner" \| "coauthor" \| "viewer"` | роль текущего пользователя: владелец / соавтор / остальные |

Собственная публичная коллекция пользователя остаётся в разделе `my` с `is_public: true`,
`role: "owner"`. Остальные поля карточки не меняются.

Пример:

```json
{
  "my": [
    { "id": 12, "name": "Кадровые вопросы", "description": null, "document_count": 40,
      "is_public": true, "role": "owner" }
  ],
  "shared_with_me": [
    { "id": 7, "name": "Отчёты 2018", "description": "…", "document_count": 9,
      "owner_username": "ivanov", "is_public": false, "role": "coauthor" }
  ],
  "public": [
    { "id": 3, "name": "Регламенты", "description": null, "document_count": 120,
      "owner_username": "petrov", "is_public": true, "role": "viewer" }
  ]
}
```

`GET /collections/{id}` — добавить те же `is_public` и `role`.

Тест на точный набор ключей карточки (`tests/test_integration_api.py`, около строки 207)
нужно обновить.

## 2. Маршрут `POST /collections/{id}/publish` — обязательно

Переводит коллекцию в публичную — так же, как `PUT /api/collections/{id}` с
`{"is_public": true}` в интерфейсе DocHub, включая соблюдение инварианта «в публичной
коллекции нет приватных документов» (сейчас это `_enforce_public_collection`).

**Запрос:** тело пустое. Параметр `dry_run` (`true`/`false`, по умолчанию `false`).

**Кто может:** владелец или соавтор (как `_get_manageable_collection`). Администратор DocHub
через интеграцию прав не получает.

**Ответ `200`:**

```json
{ "id": 7, "is_public": true, "made_public": [101, 102], "removed_private": [230] }
```

| Поле | Значение |
|---|---|
| `id` | id коллекции |
| `is_public` | состояние после вызова: `true`; при `dry_run` — текущее состояние (не меняется) |
| `made_public` | id приватных документов, которые стали (при `dry_run` — станут) публичными |
| `removed_private` | id чужих приватных документов, которые исключены (при `dry_run` — будут исключены) из коллекции |

**Правила:**
- `dry_run=true` ничего не меняет, но считает `made_public` и `removed_private` ровно так, как их
  посчитал бы настоящий вызов.
- Вызов для уже публичной коллекции ничего не меняет и возвращает `is_public: true` с пустыми
  массивами (и при `dry_run`, и без него).
- Настоящий вызов пишет событие `made_public` в журнал коллекции, как интерфейс DocHub.
- Сначала авторизация (`require_integration_user`), потом всё остальное: неавторизованный
  запрос не должен получать ни `404`, ни `422`.

**Ошибки:**

| Код | `detail` | Когда |
|---|---|---|
| `404` | `collection_not_found` | коллекции нет или пользователь её не видит |
| `403` | `not_manager` | пользователь видит коллекцию, но не владелец и не соавтор |
| `401`, `403 forbidden`, `429`, `503` | как у остальных маршрутов | |

## 3. Документация и тесты

- `docs/integration-librechat.md`: §1 (API больше не только на чтение — единственная запись это
  `publish`), §5 (новые поля и маршрут), §7 (`not_manager`), §10.
- Тесты: владелец и соавтор могут; viewer, посторонний и администратор DocHub получают `403`
  (или `404`, если не видят коллекцию); `dry_run` ничего не меняет и совпадает с настоящим
  вызовом; повторный вызов — пустые массивы; после вызова в коллекции нет приватных документов.

## Совместимость

LibreChat работает и со старым DocHub: без `is_public`/`role` он считает коллекции из
раздела `public` публичными, а свои и чужие по приглашению — с неизвестным статусом (поделиться
агентом нельзя), а на `404` от `publish` предлагает сделать коллекцию публичной в интерфейсе
DocHub.
