# Рассуждения по требованию

Модель Qwen на внутреннем шлюзе умеет отвечать с рассуждениями (`enable_thinking`) и без них.
С рассуждениями она надёжнее решает сложные задачи, но отвечает в разы дольше. Классификатор
включает рассуждения только там, где они нужны: перед каждым ответом маленький вызов модели
определяет, простое сообщение или сложное, и LibreChat подставляет в запрос
`chat_template_kwargs.enable_thinking: true` или `false`.

## Настройка

```yaml
endpoints:
  custom:
    - name: "RNT"
      # ...
      addParams:                      # база: без рассуждений (заголовки, подагенты DocHub и т. п.)
        chat_template_kwargs:
          enable_thinking: false

thinking:
  endpoints: ["RNT"]                  # чаты каких кастомных эндпоинтов решает классификатор
  classifier:
    endpoint: "RNT"                   # где работает классификатор
    model: "Qwen-3.8-27B"             # хватит небольшой быстрой модели
    timeoutMs: 8000
    maxInputChars: 4000
    # prompt: "..."                   # своя инструкция; ответ — строго simple или complex
  fallback: false                     # при таймауте, ошибке или пустом сообщении
```

Без блока `thinking` ничего не меняется. Ошибка в блоке не мешает старту: в логе строка
`[thinking] classifier disabled: invalid configuration — …`, классификатор выключен.

## Как работает

- Решение принимается один раз на ход и действует для всех агентов этого хода. Классификатор
  получает текст сообщения (до `maxInputChars` символов) и число приложенных файлов.
- Вызов классификатора идёт параллельно с подготовкой агента (загрузкой инструментов), поэтому
  к задержке ответа добавляется только то, что сверх этого времени.
- Сам классификатор всегда без рассуждений, с `temperature: 0` и лимитом 32 токена. Он идёт через
  тот же эндпоинт с его ключами и заголовками (`user-id`, `x-session-affinity`).
- Флаг ставится только в основной запрос чата. Названия диалогов, подписи активности, подагенты
  DocHub и суммаризация остаются на базе из `addParams`.
- Регенерация и продолжение ответа приходят без текста — для них действует `fallback`.
- Работает только для кастомных эндпоинтов на OpenAI-клиенте: остальные параметр не понимают.

## Диагностика

| Строка лога | Значит |
|---|---|
| `[thinking] on model=… ms=…` | классификатор решил рассуждать |
| `[thinking] off model=… ms=…` | простое сообщение, без рассуждений |
| `[thinking] classifier failed (timeout), fallback` | не уложился в `timeoutMs` |
| `[thinking] unreadable classifier answer "…", fallback` | ответ не `simple`/`complex` — поправьте `prompt` или модель |
