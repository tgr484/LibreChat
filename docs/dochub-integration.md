# Интеграция с DocHub

Агенты LibreChat работают с коллекциями документов DocHub: ищут по коллекции, читают
документы вглубь (при необходимости целиком) и обобщают материал нескольких документов.

Чтение выполняют **подагенты внутри вызовов инструментов**: инструмент сам получает текст из
DocHub, сам прогоняет его через модель и возвращает в чат только сжатый результат со ссылками
на документы и страницы. Модель чата решает, что вызвать дальше, и пишет итоговый ответ —
поэтому исследование по толстым отчётам не упирается в контекст чата.

Контракт API DocHub — `docs/integration-librechat.md` в репозитории DocHub.

---

## Инструменты

| Инструмент | Что делает | Стоимость |
|---|---|---|
| `dochub` | Список коллекций пользователя: свои, по приглашению, публичные | один запрос |
| `dochub_list` | Полный список документов коллекции: номер и название, без порога релевантности | один-десять запросов |
| `dochub_search` | Поиск внутри коллекции: номер документа, название, причина попадания, фрагмент | один запрос |
| `dochub_read` | Подагент читает один документ по вопросу — по выжимке, по частям или целиком — и возвращает ответ со ссылками на страницы | до минут |
| `dochub_survey` | Подагент ищет, разбирает несколько документов и сводит: где сходятся, где расходятся | до минут |
| `dochub_extract` | Подагент извлекает одни и те же характеристики из многих документов — для сравнительных таблиц | до минут |

Документ везде называется номером в коллекции (`№3`) — тем же, что пользователь видит в DocHub.
Модель получает указание ссылаться на документы в виде `[№3 «Название», с. 41]`.

Коллекция указывается названием, как его произнёс пользователь («Нефтяное хозяйство 2018»),
или числом. Если название подходит к нескольким коллекциям, инструмент возвращает варианты и
модель переспрашивает пользователя.

Документы, полный текст которых пользователю недоступен (чужие приватные в коллекции, где он
соавтор), читаются только по выжимке, и ответ это явно отмечает.

## Предварительные условия

1. **Эндпоинт агентов включён.** Инструменты работают только в агентах. Значение
   `ENDPOINTS=RNT` в docker-compose отключает агентов — нужно `ENDPOINTS=custom,agents`
   (или убрать переменную).
2. **Пользователи входят через LDAP**, и `ldapId` — это логин (`sAMAccountName`). Задайте явно
   `LDAP_ID=sAMAccountName`: иначе стратегия LDAP может записать в `ldapId` почту, и такие
   пользователи получат отказ. Проверка на сервере:
   ```js
   db.users.findOne({ provider: 'ldap' }, { ldapId: 1 })
   ```
   Пользователи с локальными учётками получают сообщение, что интеграция им недоступна.
3. **Таймауты прокси.** Вызов `dochub_read` или `dochub_survey` может идти до 30 минут
   (`limits.wallClockMs`, из них 90 с зарезервированы на сведение), всё это
   время SSE-соединение чата открыто. `proxy_read_timeout` на nginx-шлюзе для LibreChat должен
   быть больше `dochub.limits.wallClockMs`. Таймаут LiteLLM на один запрос к модели — не меньше
   нескольких минут.
4. **DocHub готов принимать LibreChat**: `INTEGRATION_ENABLED=true`, публичный ключ LibreChat в
   `INTEGRATION_PUBLIC_KEYS`, LDAP настроен. В `INTEGRATION_ALLOWED_CLIENTS` — адрес контейнера
   LibreChat (`/32`), а не вся подсеть.

## Настройка

### 1. Ключи

```bash
openssl ecparam -name prime256v1 -genkey -noout -out librechat-dochub.pem
openssl ec -in librechat-dochub.pem -pubout -out librechat-dochub.pub.pem
```

- `librechat-dochub.pem` — **приватный**, остаётся у LibreChat; монтируется только на чтение.
- `librechat-dochub.pub.pem` — публичный, передаётся в DocHub под своим `kid`
  (например `2026-09`). Порядок — в `docs/integration-librechat.md` DocHub, раздел «Ключи».

### 2. docker-compose (сервис LibreChat)

```yaml
volumes:
  - ./secrets/librechat-dochub.pem:/app/secrets/librechat-dochub.pem:ro
environment:
  - ENDPOINTS=custom,agents
  - LDAP_ID=sAMAccountName
```

### 3. librechat.yaml

```yaml
dochub:
  enabled: true
  baseURL: "http://dochub:8000/api/integration/v1"
  keyId: "2026-09"
  privateKeyPath: "/app/secrets/librechat-dochub.pem"
  allowedAddresses: ["dochub:8000"]
```

Остальное имеет разумные значения по умолчанию; полный блок с комментариями —
в `librechat.example.yaml`. Переменные `DOCHUB_*` из `.env.example` заполняют то, что блок
не задаёт.

Если конфигурация неполная или ключ не читается, сервер **стартует**, но инструментов DocHub
нет, а в логе одна строка `[dochub] integration disabled: <причина>`.

### 4. Агенты

Инструменты появляются в конструкторе агента как один набор **DocHub**: выбирать нужно его,
агент получает сразу все шесть инструментов.

- **Общий агент.** Набор DocHub в инструментах; коллекцию пользователь называет в чате.
- **Агент на коллекцию** (для важных коллекций, например инструкций). Тот же набор, а в
  инструкции агента:
  > Работай только с коллекцией DocHub «Инструкции по бурению». Перед ответом ищи в ней через
  > dochub_search, для деталей читай документы через dochub_read. Называй документы номером и
  > названием.

  Это мягкое закрепление — модель следует инструкции. Жёсткое закрепление даёт раздел
  «Агенты DocHub» (ниже).

## Агенты DocHub

Отдельный раздел боковой панели — упрощённый конструктор агента по одной коллекции.
Пользователь выбирает коллекцию из доступных ему в DocHub, задаёт название и (по желанию)
инструкции — агент готов, вопросы задаются в чате.

- **Коллекция закреплена на сервере** (`agent.dochub.collection_id`). Агент получает
  инструменты `dochub_agent_list`, `dochub_agent_search`, `dochub_agent_read` — в их схемах нет
  параметра коллекции, её подставляет сервер. Другие коллекции агенту недоступны, даже если
  модель о них попросит. Доступ по-прежнему проверяет DocHub — от имени пользователя, который
  пишет в чат, а не автора агента.
- **Модель задаёт администратор** в `dochub.agents` (ниже); пользователь её не выбирает.
- **Документы Office** (`create_document`, `create_presentation`, `create_spreadsheet`)
  включены по умолчанию, в форме их можно отключить.
- Сервер проверяет агента при каждом сохранении: коллекция должна быть видна сохраняющему в
  DocHub, название коллекции берётся из DocHub, набор инструментов и модель — фиксированные.
  Агента можно открыть и в обычном конструкторе (например, чтобы админ задал категорию), но
  инструменты и модель там не изменить.

### Настройка

```yaml
dochub:
  # ... блок интеграции, как выше
  agents:
    endpoint: "RNT"         # эндпоинт агентов (для кастомного — его name)
    model: "Qwen-3.8-27B"   # модель агентов DocHub
    office: true            # документы Office в новых агентах по умолчанию
```

Без `endpoint` и `model` раздела нет. Эндпоинт агентов должен быть включён (`ENDPOINTS`),
у роли — право создавать агентов.

### Как поделиться агентом

Получатели агента смогут им пользоваться, только если коллекция публичная. Поэтому:

- Агентом по **публичной** коллекции делятся как обычно — кнопка «Поделиться».
- Для **непубличной** коллекции кнопка сначала показывает предупреждение: коллекция станет
  публичной, сколько приватных документов станут публичными и сколько чужих приватных будет
  исключено (так работает DocHub). После подтверждения LibreChat публикует коллекцию через
  `POST /collections/{id}/publish` и открывает обычный диалог шаринга. Опубликовать может
  только владелец или соавтор коллекции.
- То же правило проверяет сервер при любом изменении доступа к агенту (в том числе из обычного
  конструктора и для удалённого агента): выдача доступа по непубличной коллекции получает
  `409 dochub_collection_private`. Отзыв доступа не ограничивается. Правило одно для всех,
  включая администратора.
- Чтобы пользователи могли делиться агентами, у роли `USER` должно быть право `AGENTS.SHARE`
  (по умолчанию выключено), для публикации «всем» — `AGENTS.SHARE_PUBLIC`.

**Публичный агент администратора** (например, по кадровым вопросам): админ, вошедший через
LDAP, создаёт агента по публичной коллекции и делится им «со всеми»; категорию и продвижение в
маркетплейсе задаёт через обычный конструктор.

Требования к DocHub (поля `is_public`/`role`, маршрут публикации) — в
`docs/dochub-agents-contract.md`. Со старым DocHub раздел работает, но собственные коллекции
считаются непубличными (поделиться нельзя), а публикация предлагает сделать коллекцию
публичной в интерфейсе DocHub.

## Бюджет одного вызова

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `limits.wallClockMs` | 1 800 000 | страховочный предел времени вызова; по истечении возвращается частичный ответ |
| `limits.reduceReserveMs` | 90 000 | время на сведение: за столько до предела чтение останавливается, а незаконченные разборы прерываются |
| `limits.llmCallTimeoutMs` | 240 000 | один запрос к модели; зависший запрос теряет одну часть, а не весь вызов |
| `limits.maxHttpRequests` | 400 | запросов в DocHub (у DocHub предел 120 в минуту на пользователя) |
| `limits.maxLlmCalls` | 300 | вызовов модели на разбор частей; сведениям дополнительно доступно ещё 16 |
| `limits.maxChapters` | 40 | частей документа, которые `dochub_read` читает; больше — модель выбирает нужные |
| `limits.maxDocuments` | 6 | документов в `dochub_survey` (потолок 12) |
| `limits.chapterConcurrency` / `documentConcurrency` | 4 / 3 | параллельные вызовы модели |
| `limits.resultCharLimit` | 32 000 | размер ответа инструмента в контексте чата |

Исчерпание любого предела даёт **частичный ответ** с пометкой вида
«⚠ Прочитано 7 из 19 частей…», а не ошибку.

`dochub_survey` делит время между документами поровну: время, оставшееся на чтение, делится на
число ещё не начатых «волн» (по `documentConcurrency` документов в волне), и у каждого документа
свой резерв на сведение. Число частей на документ ограничено и глубиной (`summaries` — 3,
`full` — `maxChapters / 2`), и долей `maxLlmCalls`: при `full` и 8 документах читается до
`300 / 8 − 1` частей на документ. Если шлюз модели не справляется с нагрузкой,
первым делом снизьте `chapterConcurrency` до 2.

Модель подагента по умолчанию — та же, что у чата (эндпоинт и модель агента). Другую можно
задать в `dochub.agent.endpoint` / `dochub.agent.model`.

**Режим размышлений.** Выписки и сведения не требуют рассуждений, а думающая модель тратит на них
в разы больше времени и выходных токенов. По умолчанию (`dochub.agent.thinking: false`) в запросах
подагентов к кастомным эндпоинтам передаётся `chat_template_kwargs: {enable_thinking: false}` —
это понимают vLLM и SGLang с шаблоном Qwen. Если шлюз такой параметр отвергает, задайте
`thinking: true`. Ответ, оборванный внутри `<think>`, считается неудачным разбором и в сводку не
попадает. `maxOutputTokens` по умолчанию 12000: русское сведение на 32 000 символов (`resultCharLimit`)
занимает около 11 000 токенов. Уменьшая один, уменьшайте и другой.

## Безопасность

- Пользователь для DocHub — **только** `ldapId` из сессии LDAP. В схемах инструментов нет поля
  идентичности: модель не может запросить чужие документы.
- Каждый запрос в DocHub подписан своим ES256-токеном со сроком 60 с и уникальным `jti`.
  Приватный ключ читается один раз, в логи и ответы API не попадает.
- `dochub_read` читает только документы, пришедшие из списка или поиска этой коллекции:
  маршруты документов в DocHub коллекцией не ограничены, ограничение делает LibreChat.
- Права на документы проверяет DocHub; администратор LibreChat прав в DocHub не получает.

## Диагностика

Строки лога:

| Строка | Значит |
|---|---|
| `[dochub] integration disabled: …` | конфигурация не принята, инструментов нет |
| `[dochub] sub=… route=… status=… jti=… ms=…` | один запрос в DocHub (без токена и текста) |
| `[dochub] tool=… sub=… http=… llm=… ms=…` | итог одного вызова инструмента |
| `[dochub] dochub_… refused: subject not_ldap` | пользователь вошёл не через LDAP |

Частые ответы модели пользователю:

| Ситуация | Что проверить |
|---|---|
| «не удалось пройти аутентификацию в DocHub» | `kid` и публичный ключ в DocHub, синхронизация часов (NTP, допуск 30 с) |
| «интеграция выключена на стороне DocHub» | `INTEGRATION_ENABLED` в DocHub, nginx не должен стоять между сервисами |
| «нет доступа» | группа LDAP `dochub-users`, `INTEGRATION_ALLOWED_CLIENTS` |
| «учётная запись не сопоставлена» | `LDAP_ID`, значение `ldapId` у пользователя |
| «поиск занят другим запросом» | у пользователя открыт чат в интерфейсе DocHub |
| «глубокое чтение недоступно» | эндпоинт и модель агента, `dochub.agent.*` |
